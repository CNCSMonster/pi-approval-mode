## 一、核心选型结论与推荐配置 (TL;DR)

经过对全网主流专职决策模型（阿里百炼、Cloudflare Clef、TypeSafe Jev）与通用代码/决策模型（OpenAI GPT-6 Luna、Anthropic Claude Haiku 4.5、DeepSeek-Flash 等）在 **47 题高难对抗集** 与 **74 题真实编码场景集** 的全量基准压测，得出当前生产环境下的**黄金配置组合**：

* **Stage 1（高频快速守门）**：**`deepseek/deepseek-flash`**（DeepSeek 官方直连，时延 ~749ms）
* **Stage 2（深度权威复核）**：**`openrouter/anthropic/claude-haiku-5.5`**（thinking: `low`；等权 92 vs 74~76、P50 1446ms vs 2175ms、FP 5 vs 24~27）
* **选型结论（2026-10-16 复测 + 阈值扫描 + 组合重放）**：**维持现役组合不变**，证据链与差距记录见 §六

## 二、双阶段分工哲学与第一性原理

审批分类器架构面临两个天然对立的工程矛盾：**终端敲代码的高频极速流畅体验** vs **复杂长链黑客攻击的绝对零漏报底线**。任何单一模型都无法单独兼顾。因此，系统确立了**纵深防御流水线**：

```
                    待审批工具调用 (Pending Tool Call)
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第一道] Layer 1 静态启发式防线 (0ms，100% 确定性秒杀)                    │
│  - 纯正则与路径黑名单秒级硬拦截 (git push -f, rm -rf /, .env*, id_rsa*) │
│  - 输入控制字符清洗与全角 Unicode NFKC 归一化 (防提示注入绕过)           │
│  👉 将绝大多数已知高危在 0ms 拦截，不给下游模型犯错机会                  │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ (常规/非黑名单调用)
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第二道] Stage 1 极速初筛守门 (预算 ≤ 1500ms，实测 P50 749ms)          │
│  - 推荐模型：deepseek/deepseek-flash (DeepSeek 官方平台直连)           │
│  - 策略契约：【宁杀错不放过】。                                        │
│    * 确信为安全的日常只读/开发操作 (git status, read, npm test) ➔ 放行 │
│    * 存疑 / 超时 / 异常 / Block ➔ 全部上浮交给 Stage 2 终审            │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ (存疑 / 拦截的动作)
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第三道] Stage 2 深度权威复核 (预算 ≤ 4500ms，实测 P50 1446ms)          │
│  - 推荐模型：openrouter/anthropic/claude-haiku-5.5 (thinking: "low")   │
│  - 核心职责：高准度低误报仲裁复核；负责为被 Stage 1 误报的操作【洗冤】；│
│  - 若确认为违规危险操作，生成专业、严密的人类可读解释弹窗警告用户！    │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、核心技术洞察与实测证据链

### 1. 为什么 Stage 2 推荐 `anthropic/claude-haiku-5.5`？
* **高准度与低误报的最佳平衡（等权 92 vs 74~76，FP 5 vs 24~27）**：
  在 121 题全量基准评测集中，`claude-haiku-5.5` 等权正确率达 **92%**（111/121），误报仅 5 起（FN 5 / FP 5）；相比之下，`gpt-6-luna` 虽漏报低（FN 1），但误报高达 24~27 起（过度保守防御），等权正确率仅 74~76，严重打扰正常开发工作流；
* **更优的响应时延（P50 1446ms vs 2175ms）**：
  `claude-haiku-5.5` 实测 P50 时延仅 **1446ms**，3s 内达标率 88%；而 `gpt-6-luna` 实测 P50 达 2175ms，1.5s 达标率为 0%；
* **全链路协同提升（综合准确率 95%）**：
  在 SUT 全链路实测中，Stage 1（`deepseek/deepseek-flash`）+ Stage 2（`openrouter/anthropic/claude-haiku-5.5`）组合取得 **95%**（115/121）的端到端综合准确率（单模型 Haiku 5.5 基线为 91.7%），全链路 P50 延迟仅 **856ms**。

### 2. 为什么 Stage 2 推荐配置低思考档位（`thinking: "low"`）？
针对审查分类任务，实测证据表明：
* **有效识破复杂提示注入**：低思考档位（`low`）引入必要的轻量思维链分析，能够有效识破间接注入与带内提示词绕过攻击，显著提升安全防守质量；
* **时延严格控制在预算内**：在 `low` 思考档位下，实测 P50 时延仅 **1446ms**，完全处于 Stage 2 预算窗口（≤ 4500ms）的安全范围内，避免无界长思考导致的超时中断；
* **兼顾极佳经济性**：轻量思考 Token 消耗克制，既获得高确定性语义判断，又避免无谓的计费膨胀。

### 3. 为什么 Stage 1 推荐 DeepSeek-Flash？时延与缓存真相
* **时延无可替代**：
  Stage 1 处于开发者敲代码的高频热路径上，DeepSeek-Flash 实测 **749ms**，比 Luna 快 2.8 倍，完全不打断开发心流；
* **缓存命中（Prompt Cache）的第一性原理**：
  * **短会话阶段（< 1000 tokens）**：由于 DeepSeek 官方有 1024 tokens 的缓存触发阈值，无法命中缓存。此时按官方最坏情况未命中单价（1.00 ~ 2.00 元/1M）兜底，**单次审查开销也仅为 0.04 分钱**；
  * **长链路会话阶段（> 1000 tokens）**：在真实多轮开发中，由于滑动窗口内历史前缀保持静态不变，**DeepSeek 官方前缀缓存命中率高达 80% ~ 90%**，单次开销被打到地板价（**0.02 分钱**）；
  * **并行工具调用（Parallel Tool Calls）红利**：当主模型一次性回复多个工具调用（如连续 read 3 个文件）时，后续调用 100% 命中缓存，时延进一步降至 **300ms 级别**。

## 五、降级与高可用保障策略

当网络出现波动或服务商故障时，系统内置以下自动保护：
1. **Stage 1 异常熔断接管**：
   若 Stage 1 发生超时（> 1500ms）或网络异常，系统自动无缝升级至 Stage 2 深度复核，终端记录健康度降级告警，但保障安全底线绝不放行；
2. **全流程不可用保底**：
   若两阶段均因断网无法连通，系统自动触发 `fallbackHeuristicCheck`（离线启发式安全兜底），以最严格标准弹出人工审批框，杜绝无感越权。

**离线阈值扫描**（score = 判恶意概率，现行阈值 0.5；纯本地重算，零 API 调用）：

* `openrouter/microsoft/microsoft-decision-1`（以下简称 ms）：拐点 θ=0.033 把漏报 3→0，上浮率下界
  48.8%→51.2%（+3 题恰为漏报题自身转上浮，FP 零新增）；
* `openrouter/typesafe/jev-1.13`（以下简称 jev）：拐点 θ=0.26 把漏报 3→0，下界 52.9%→55.4%；
* `deepseek/deepseek-flash`（以下简称 deepseek）：聊天链路无概率分，阈值无抓手，漏报 2 无离线改善路径；
* 上浮率上界不可量化：bench 只落盘错题分数，正确放行题的概率分缺失，最坏上界 100%——
  阈值落地前必须先补概率分落盘。

**两阶段组合端到端重放**（Stage 2 = `openrouter/anthropic/claude-haiku-5.5`，thinking `off`；
23 次真实调用，实际成本 0.0253）：

* 生产契约实证：deepseek 漏报 2 不入 Stage 2 → **组合漏报恒等 2**；Stage 2 挽回其 FP 的
  7/11（63.6%），残余 4 题两阶段均拦（组合 FP 4）；
* 拐点漏报 3 题（两候选共用同一组题）Stage 2 **3/3 拦截** → 两候选拐点下组合漏报 0（实测）；
  FP 挽回部分覆盖（ms 4/5、jev 5/8），全量口径下界 ms 40%、jev 33.3%，待补跑；
* Stage 2 主导组合时延：实测 P50 2440–2856ms / P95 3412–3570ms（≤3s 达标 67–90%，≤5s 100%）；
  组合 P50 估算 2.9–3.1s、P95 4.1–4.3s（链路加和近似——逐题 Stage 1 时延未落盘，
  无法算精确混合分位数）。

**选型结论：维持现役**（Stage 1 `deepseek/deepseek-flash` + Stage 2 `openrouter/anthropic/claude-haiku-5.5`）。依据：

1. 三候选安全加权 38/20/10 全部低于 80 线，无一合格；
2. 复合标准（漏报×延迟为主）：现役 FN 2 / P50 412ms，优于两候选基线（FN 3 / 681ms、FN 3 / 469ms）；
3. 两候选拐点 FN→0 有 Stage 2 实测支撑，但换人的两道前置证据未闭合——上浮带上界不可量化、
   FP 全量挽回未测（尚未补测），不足以支撑切换；
4. 成本为辅项：ms 便宜约 26×，不改判。

5. 反向对照（2026-10-17）：`deepseek/deepseek-flash`（thinking=off）双阶段接管全链路三轮实测不达标

   Stage 1 快筛。

**差距记录**：

* 现役漏报 2 题无阈值抓手，Stage 2 实测可拦但生产链路送不进——
  属现役链路结构性差距，需概率分或判链工程化才能解；
