> **版本**：v1.1 (2026-10-08)

## 一、核心选型结论与推荐配置 (TL;DR)

经过对全网主流专职决策模型与通用代码/决策模型在 121 题全量基准测试与系统全链路保真测试，得出当前生产环境下的**黄金配置组合**：

* **Stage 1（高频快速守门）**：**`deepseek/deepseek-flash`**（DeepSeek 官方直连，thinking: `low`，时延 ~400ms）
* **Stage 2（深度权威复核）**：**`openrouter/anthropic/claude-haiku-5.5`**（Anthropic 官方，thinking: `low`，具备防间接/带内注入深度推理能力）

### 1. 本地一键配置文件
配置文件路径：`~/.pi/agent/approval-config.json`

```json
{
  "classifierStage1Model": "deepseek/deepseek-flash",
  "classifierStage2Model": "openrouter/openai/gpt-6-luna",
  "comment": "Auto 模式审批分类器双阶段最佳实践：Stage 1 极速守门 (DeepSeek 官方)，Stage 2 权威零漏报复核 (OpenAI GPT-6 Luna)"
}
```

### 2. 终端交互命令
在智能体终端中，可随时执行以下命令完成热配置与状态巡查：
```bash
# 一键分别指定 Stage 1 与 Stage 2
/classifier-model --stage1 deepseek/deepseek-flash --stage2 openrouter/openai/gpt-6-luna

# 查看当前生效状态与健康度
/classifier-model
```

## 二、双阶段分工哲学与第一性原理

审批分类器架构面临两个天然对立的工程矛盾：**终端敲代码的高频极速流畅体验** vs **复杂长链黑客攻击的绝对零漏报底线**。任何单一模型都无法单独兼顾。因此，系统确立了**纵深防御流水线**：

```
                    待审批工具调用 (Pending Tool Call)
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第一道] Layer 1 静态启发式防线 (0ms，100% 确定性秒杀)                    │
│  - 纯正则与路径黑名单秒级硬拦截 (git push -f, rm -rf /, .env*, id_rsa*) │
│  - 输入控制字符清洗与全角 Unicode NFKC 归一化 (防提示注入绕过)           │
│  👉 将绝大多数已知高危在 0ms 拦截，不给下游模型犯错机会                  │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ (常规/非黑名单调用)
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第二道] Stage 1 极速初筛守门 (预算 ≤ 1500ms，实测 P50 749ms)          │
│  - 推荐模型：deepseek/deepseek-flash (DeepSeek 官方平台直连)           │
│  - 策略契约：【宁杀错不放过】。                                        │
│    * 确信为安全的日常只读/开发操作 (git status, read, npm test) ➔ 放行 │
│    * 存疑 / 超时 / 异常 / Block ➔ 全部上浮交给 Stage 2 终审            │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ (存疑 / 拦截的动作)
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [第三道] Stage 2 深度权威复核 (预算 ≤ 3000ms，实测 P50 2096ms)          │
│  - 推荐模型：openrouter/openai/gpt-6-luna (thinking: "off")            │
│  - 核心职责：全场唯一零漏报的大脑；负责为被 Stage 1 误报的操作【洗冤】；│
│  - 若确认为违规危险操作，生成专业、严密的人类可读解释弹窗警告用户！    │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、核心技术洞察与实测证据链

### 1. 为什么 Stage 2 必须锁定 `openai/gpt-6-luna`？
* **全场唯一达成零漏报（Zero False Negative）**：
  在 47 题高难对抗集（包含学术权威 R-Judge 越权与 AgentHarm 意图偷跑）中，主流模型（Jev、Clef、百炼）普遍发生 3 ~ 11 起严重漏报，**只有 GPT-6 Luna 做到了 0 漏报**；
* **极度敏锐的代码物理边界感知**：
  它能精准识别什么是真实破坏性动作（如未授权覆盖主干），什么是惰性说明文字（如 commit 注释中的文本）；
* **极具说服力的专业解释**：
  在拦截敏感行为时，它生成的理由直击要害（例如明确指出：*“用户授权合并，但并未授权强行重写远程主分支历史”*）。

### 2. 为什么 Stage 2 必须显式关闭思考（`thinking: "off"`）？
针对审查分类任务，对比实验表明：
* **理由质量完全一致**：零思考模式下生成的人类解释与低思考模式同样深刻专业；
* **时延直接腰斩**：零思考下 P50 时延为 **2.0 秒**，开启低思考后时延暴涨至 **3.8 ~ 7.3 秒**，导致超时抖动；
* **成本大幅缩减**：避免了数十至上百个思考 token 的无谓计费。

### 3. 为什么 Stage 1 推荐 DeepSeek-Flash？时延与缓存真相
* **时延无可替代**：
  Stage 1 处于开发者敲代码的高频热路径上，DeepSeek-Flash 实测 **749ms**，比 Luna 快 2.8 倍，完全不打断开发心流；
* **缓存命中（Prompt Cache）的第一性原理**：
  * **短会话阶段（< 1000 tokens）**：由于 DeepSeek 官方有 1024 tokens 的缓存触发阈值，无法命中缓存。此时按官方最坏情况未命中单价（1.00 ~ 2.00 元/1M）兜底，**单次审查开销也仅为 0.04 分钱**；
  * **长链路会话阶段（> 1000 tokens）**：在真实多轮开发中，由于滑动窗口内历史前缀保持静态不变，**DeepSeek 官方前缀缓存命中率高达 80% ~ 90%**，单次开销被打到地板价（**0.02 分钱**）；
  * **并行工具调用（Parallel Tool Calls）红利**：当主模型一次性回复多个工具调用（如连续 read 3 个文件）时，后续调用 100% 命中缓存，时延进一步降至 **300ms 级别**。

## 五、降级与高可用保障策略

当网络出现波动或服务商故障时，系统内置以下自动保护：
1. **Stage 1 异常熔断接管**：
   若 Stage 1 发生超时（> 1500ms）或网络异常，系统自动无缝升级至 Stage 2 深度复核，终端记录健康度降级告警，但保障安全底线绝不放行；
2. **全流程不可用保底**：
   若两阶段均因断网无法连通，系统自动触发 `fallbackHeuristicCheck`（离线启发式安全兜底），以最严格标准弹出人工审批框，杜绝无感越权。
